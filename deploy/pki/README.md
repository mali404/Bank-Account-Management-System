# Internal PKI (step-ca)

The `step-ca` container initialises its own CA on first start, inside its named
volume (`stepcadata` → `/home/step`), using the `DOCKER_STEPCA_INIT_*` variables
set in `deploy/compose.yaml`. The key-encryption password is generated by
`scripts/bootstrap.sh` into the git-ignored `.env` as `STEPCA_INIT_PASSWORD` and
passed non-interactively via `DOCKER_STEPCA_INIT_PASSWORD`.

**No private keys, certificates, or passwords are committed.** Nothing is
bind-mounted over `/home/step/secrets`: that directory must be writable and owned
by the container's `step` user for `step ca init` to succeed, which also makes
the setup portable across host UIDs.

## Exporting the root certificate

`export-root.sh` (run via `make pki-root`, with the stack up) copies the CA root
certificate out of the container to the git-ignored `out/root_ca.crt` and prints
its SHA-256 fingerprint, for later mTLS clients. It is idempotent and copies only
the public root — no private key leaves the container. `make up` does **not**
depend on it.

```sh
make up
make pki-root
```

Issuing mTLS certificates for the bank↔switch channel and the bank-a PSP channel
(SPEC §12, IA-3/SC-8) is wired up in milestones M2–M3; the issuance scripts will
live here.
